# Журнал полевых работ и затрат

Веб-приложение для учёта полевых работ в сельскохозяйственном хозяйстве. Цель проекта — дать агроному возможность вести журнал работ, а руководителю — видеть общие затраты и затраты на гектар по каждому полю за сезон.

Разработчик — Гринь Вероника. Рабочая ветка — `veronika`.

## Быстрый запуск бэкенда

Понадобятся Git и Python 3.12. Бэкенд использует Django, Django REST Framework и SQLite.

```bash
git clone --branch veronika https://github.com/nikolyyya/agro-field-log.git
cd agro-field-log/backend
```

Создай виртуальное окружение и скопируй шаблон настроек. Для Linux и WSL выполни:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Для Windows PowerShell выполни:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Сгенерируй ключ и вставь полученную строку после `DJANGO_SECRET_KEY=` в локальном файле `backend/.env`. В командах ниже для PowerShell используй `.\.venv\Scripts\python.exe` вместо `python`.

```bash
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

После сохранения `.env` проверь настройки, создай таблицы и запусти сервер.

```bash
python manage.py check
python manage.py migrate
python manage.py runserver
```

Проверка запуска — `GET http://127.0.0.1:8000/api/health/` возвращает `{"status":"ok"}`. Для доступа к `/admin/` создай локального администратора командой `python manage.py createsuperuser`.

| Переменная | Назначение |
| --- | --- |
| `DJANGO_SECRET_KEY` | Секретный ключ Django. Задаётся при локальной настройке |
| `DJANGO_DEBUG` | `true` включает режим отладки для локальной разработки |
| `DJANGO_ALLOWED_HOSTS` | Имена хостов через запятую |

## Модели и администрирование

После миграций в разделе «Журнал полевых работ» в `/admin/` доступны поля,
культуры, сезоны, посевы и записи о работах. Сначала создай поле, культуру
и сезон, затем посев и запись о работе. По посеву определяется, к какому полю,
культуре и сезону относится работа.

Площадь поля хранится в гектарах и должна быть больше нуля. Затраты на одну
работу указываются в рублях с точностью до копеек, допустима нулевая сумма.
Дата окончания сезона может совпадать с датой начала или быть позже неё.
Связанные записи защищены от каскадного удаления через Django.

## Вход и права

После `python manage.py migrate` в Django Admin появятся две группы.
Создай пользователя в разделе «Пользователи» и назначь ему нужную группу.

| Группа | Справочники и посевы | Записи журнала | Отчёт по затратам |
| --- | --- | --- | --- |
| Агроном | Просмотр | Просмотр, создание, изменение, удаление | — |
| Руководитель | Просмотр | Просмотр | Просмотр |

Для доступа пользователя к `/admin/` дополнительно включи «Статус персонала».
Для входа через API достаточно активной учётной записи:

```http
POST /api/auth/token/
Content-Type: application/json

{"username":"<логин>","password":"<пароль>"}
```

При верном логине и пароле сервер возвращает `200` и JSON с полем `token`.
Передавай его в заголовке `Authorization: Token <токен>` защищённых запросов.
Токен можно отозвать удалением в Django Admin. `GET /api/health/` доступен
без учётной записи.

## API журнала

- `GET /api/work-entries/` возвращает список. Фильтры `field` и `season`
  принимают числовые идентификаторы и могут использоваться вместе.
- `POST /api/work-entries/` создаёт запись. В теле передай `planting`,
  `work_date`, `title` и `cost`. Поле `notes` можно опустить.
- `GET`, `PUT`, `PATCH` и `DELETE /api/work-entries/{id}/` читают,
  заменяют, частично обновляют и удаляют отдельную запись.
- `GET /api/fields/`, `GET /api/seasons/` и `GET /api/plantings/` возвращают
  справочники. Каждый ресурс также можно получить по идентификатору.

В ответе `field` и `season` определяются по посеву. Дата работы в формате
`YYYY-MM-DD` должна попадать в сезон посева включительно. Затраты можно
передать строкой, например `"1250.50"`. В ответах затраты также представлены
строкой. Ошибки валидации возвращаются с кодом `400`.

## Отчёт, демоданные и проверки

Из каталога `backend` после миграций выполни:

```bash
python manage.py seed_demo
python manage.py test
```

Команда добавляет поля, культуры, сезоны, посевы и работы с демоданными.
Повторный запуск использует ранее загруженные записи. Для входа создай
учётную запись руководителя или агронома в Django Admin и назначь ей группу.

Руководитель может открыть `GET /api/reports/costs/` с токеном. В строке
«Демо — Северное» за «Демо — 2026» сумма составляет `12500.00` руб.,
а затраты на гектар — `1000.00` руб./га. Тесты проверяют вход, права обеих
ролей, операции журнала, валидацию и расчёт отчёта.

## Этапы бэкенда

1. Основа Django-проекта, локальная настройка и проверка запуска API.

3. Аутентификация и права. Агроном ведёт журнал, руководитель просматривает данные и отчёты.

5. Отчёт по затратам, демонстрационные данные, проверка прав доступа и документация API для React.
